# 1강 · AI로 첫 CAD 모델 만들기

목표: 조건을 정하고 첫 설계 파일을 생성해 형상과 치수를 확인한다. CAD는 물건의 형상·치수 설계이고 SMLib는 기하 계산, 코덱스는 코드 작성 역할이다.

## 준비

기존 강의 저장소의 `ai-cad/lesson-01/start/`를 별도 작업 폴더로 복사하세요. 상위 README의 Python3.12 가상환경·설치를 마친 뒤 `python environment_check.py`를 실행합니다. `준비 완료`와 설치 버전을 확인합니다.

코덱스 앱에서 이 강의의 `start/` 폴더를 열거나, 해당 폴더의 터미널에서 `codex`를 실행하고 `PROMPTS.md`의 요청을 입력합니다. 필요한 코드 작성·실행·검사를 같은 대화에서 진행합니다. 생성된 파일과 실행 결과를 직접 확인한 뒤 다음 요청으로 넘어갑니다.

별도 웹 입력창, `workshop.py`, 로컬 웹 서버, Codex CLI 설치는 앱 실습의 필수 조건이 아닙니다. CLI를 이미 사용한다면 같은 폴더에서 동일한 요청을 보낼 수 있습니다. 생성 코드가 예시와 달라도 요구 치수와 독립 검사 결과로 성공을 판단합니다.

## 1. 치수표 읽기

SPEC.md의 기본 설계만 사용합니다. 가로80, 세로30, 두께3, 케이블 구멍 지름6. 구멍 중심x=-27,-9,9,27, y=0. 고정구멍은(-34,-9),(34,-9), 지름3.5. 전면 틈은폭2, y=0~15. 바닥z=0, 모서리반경2. 추가가공구멍은3강에서만만듭니다.

## 2. 코덱스에 요청

> 케이블 네 개를 정리할 받침을 만들어줘. SPEC.md의 기본 치수만 참고하고 구멍 지름6mm, 두께3mm로 해줘. 3강의 추가 구멍은 아직 만들지 마. Python model.py에 --hole, --thickness, --out 인자를 만들고 STEP·STL 파일과 viewer.html을 저장하게 해줘. CAD-API.md와 공식 문서를 참고해줘.

필수 조건이 빠지면 묻도록 하고, 추측한 치수는 확인합니다. 생성 후 model.py를 열어 입력값과 저장 경로를 확인합니다. 지름은 원기둥 생성 시 반지름의2배입니다.

## 3. 저장 이름 확인

생성 코드가 다른 파일 이름을 선택했다면 PROMPTS.md의 요청4로 `organizer.step`, `organizer.stl`, `verified.json`에 맞춰 주세요. 형상은 유지하고 다시 생성·검사합니다. 다음 강의에서 같은 이름을 사용합니다.

## 4. 실행 결과 확인

```sh
python model.py --hole 6 --thickness 3 --out outputs/before
```

outputs/before/organizer.step과 organizer.stl이 생겨야 합니다. viewer.html은 인터넷이 연결된 브라우저에서 열 수 있습니다. HTML은 입체 결과를 보는 선택 뷰어입니다. STEP/STL을 열 수 있는 CAD 프로그램을 사용해도 됩니다. 프롬프트 입력은 코덱스 앱에서 계속합니다.

## 5. 직접 검사

```sh
python verify_one.py --file outputs/before/organizer.step --hole 6 --thickness 3 --report outputs/before/verified.json
```

PASS와 dimensions_mm≈[80,30,3], hole_mm=6을 확인합니다. 하나의 정상 솔리드, 케이블구멍·고정구멍 위치, 전면틈, 원하지 않은 중앙구멍 부재까지 검사합니다. 예상과 다르면 완료 메시지보다 모델과 검사 실패 항목을 먼저 봅니다. 잘못 추가된 중앙 구멍이 있으면 기본 설계에서 제외하라고 수정한 뒤 재실행하세요.

## 6. 형식 구분

STEP: 면과 입체를 CAD 사이에서 전달. STL: 표면을 삼각형으로 나눈 메시. Python 코드: 설계 입력과 생성 과정을 재사용. 세 가지를 함께 보관합니다.


## 코덱스 앱에서 실행시키기

아래 명령은 직접 입력해야 하는 별도 학습 목표가 아니라, 코덱스가 실제로 무엇을 실행했는지 대조하는 참고입니다. “이 명령을 현재 가상환경으로 실행하고, 종료 코드와 검사 결과를 보여줘”라고 요청해도 됩니다. 완료 답변만 보고 넘어가지 말고 생성 파일·실제 실행 출력·검사 JSON을 함께 확인합니다.

## 화면에서 짚어 볼 부분

요청에서는 바꿀 치수·유지 조건·출력 폴더를 구분해 읽습니다. 실행 후에는 코덱스가 실제 실행한 명령과 종료 코드, 검사 JSON을 확인합니다. 결과 뷰어는 입체를 보는 용도이고 프롬프트는 계속 코덱스에서 입력합니다.
