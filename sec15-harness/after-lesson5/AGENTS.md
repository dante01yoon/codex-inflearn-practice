# ev-booking 작업 지침

## 작업 시작 전에 읽을 문서

이 폴더에서 작업을 시작하기 전에 다음 세 문서를 모두 먼저 읽는다.

1. [docs/prd.md](docs/prd.md): 제품 목적, 범위, 확정 정책, 열린 질문
2. [docs/acceptance.md](docs/acceptance.md): US별 GIVEN/WHEN/THEN 수용 기준과 조건부 기준
3. [docs/tasks.md](docs/tasks.md): 구현 작업, 관련 US·AC, 완료 조건, 선행 작업, 구현 전 확인 목록

## 정책과 작업 범위

- 문서에 없는 정책은 임의로 정하지 말고 사용자에게 물어본다. 금액, 시간 경계, 자격, 상태 전이, 대기 순서, 권한, 실패 처리도 이 원칙을 따른다.
- 문서끼리 충돌하거나 해석이 여러 가지면 관련 문서·US·AC·T 번호를 제시하고 사용자에게 확인한다. 작업 목록만으로 PRD·수용 기준의 정책을 바꾸지 않는다.
- 조건부 AC와 tasks.md의 C 항목은 미확정 상태이다. 단순 문서 승인만으로 확정됐다고 간주하지 않는다. 해당 동작을 구현하기 전에 답변을 받고 관련 문서를 함께 갱신한다.
- 기술 구성이 아직 확정되지 않았다면 T-01의 합의부터 수행한다. 제품 정책에 영향을 주지 않는 내부 구현 선택은 합의한 구성 안에서 결정할 수 있다.
- 요청받은 T 작업의 선행 조건과 실제 완료 근거를 확인하고, 그 작업의 범위와 완료 조건에 맞춰 수행한다. 필요한 추가 작업은 별도로 설명한다.

## 막혔을 때의 처리

- 훅이 작업을 차단하면 다른 도구·명령·경로로 우회하거나 훅을 수정·비활성화하지 않는다. 즉시 `BLOCKED`로 멈추고, 차단한 훅·작업·이유와 사용자가 고를 수 있는 선택지 및 각 선택의 영향을 보고한다. 훅이 수정을 요청하더라도 이 중단 규칙을 우선한다.
- 정책 변경으로 테스트 수정이 필요하면 구현을 중단하고 테스트를 직접 고치지 않는다. 기존 기준 → 바뀔 기준, 관련 문서·US·AC·T·C 번호, 테스트 파일·정확한 테스트 이름·현재 기대값·변경할 기대값을 정리해 사용자에게 넘긴다. 사용자 결정 후 별도 테스트 작성 단계에서 다시 확인·실패 검증을 거쳐 구현을 재개한다.
- 같은 테스트(파일 경로 + 전체 테스트 이름)가 세 번 연속 실패하면 추가 수정·재실행을 중단하고 `BLOCKED`로 멈춘다. 세 번의 실행 명령·실패 내용·시도한 수정·남은 원인과 기록 위치를 남겨 사용자에게 보고한다. 테스트 이름·기대값·실행 설정 변경으로 실패를 숨기거나 횟수를 초기화하지 않는다.
- 하네스 구성과 자동 검사 범위·한계는 [docs/harness.md](docs/harness.md)를 참조한다.

## 예약·결제 도메인 규칙

- 금액은 원(KRW) 단위 정수로만 저장·계산·전달한다. 금액·환불 정책은 [PRD 4.2](docs/prd.md)를 따른다.
- 시간은 서울 시간(`Asia/Seoul`)과 시연용 시계를 기준으로 하고, 예약은 `[시작, 종료)` 구간으로 처리한다. 상세는 [PRD 4.2·4.2.1](docs/prd.md)과 [US-04 수용 기준](docs/acceptance.md)을 따른다.
- 예약 상태·상태 전이·처리 순서와 대기·승계 순서는 [PRD 4.2·4.2.1](docs/prd.md)를 따른다. 미정 순서는 임의로 정하지 않는다.
- 환불·체크인·겹침 판정 로직은 `src/rules`의 순수 함수에만 둔다. 화면·API에서는 호출만 하고 규칙을 중복 구현하지 않는다. 상세는 [US-04·07·08 수용 기준](docs/acceptance.md)과 [C-10·T-13·T-22·T-25](docs/tasks.md)를 참조한다.
- 결제·환불은 토스페이먼츠 테스트 키(`test_` 접두사)만 사용한다. 키 값은 `.env`에만 보관하고 코드·문서·로그·Git에 노출하지 않는다. 결제·환불 동작은 [US-05 수용 기준](docs/acceptance.md)과 [T-15~T-19·T-47](docs/tasks.md)을 따른다.

## 데이터·시연·검증

- 학습용 로컬 모바일 웹이다. 배포하지 않는다. 실제 충전소 이용·주차면·충전량을 보장하지 않는다.
- 충전소 원본은 `../ev-map/data`이다. 원본을 임의로 수정하거나 재수집하지 않는다.
- 결제·환불은 토스페이먼츠 테스트 모드만 사용한다. 실제 결제를 수행하지 않는다. 인증키·비밀값을 코드, 문서, 로그에 노출하지 않는다.
- 서비스 정책 시간은 서울 시간과 문서의 시연용 시계를 따른다.
- 관련 AC를 검증하고 `PASS / FAIL / BLOCKED / NOT_RUN`을 정확히 기록한다. 정적 확인, 모의 처리, 브라우저 검증, 토스 테스트 실연결을 구분하며 실행하지 않은 검사를 통과로 보고하지 않는다.
