# 브라우저 예약 화면 구현 제안

상태: 2026-10-09 사용자 구성 승인. 신규 테스트 생략·미정 표시·기한 진행 노쇼 버튼 지시 수신.
실제 구현·검증 범위는 `browser-preview-validation.md`를 따른다.
사용자 요청: 추가 설치 없이 로컬 지도에서 충전소·시간 선택, 중복 예약 방지,
예약금 3,000원 토스 테스트 결제, 노쇼와 대기 승계 표시, 실행 주소 제공.

## T-01 / C-10 구성 제안

- 이미 있는 Node.js 24와 TypeScript 사용. Node 내장 HTTP 서버와 HTML/CSS/JavaScript로 화면을 구성한다. 패키지 설치와 배포는 하지 않는다.
- 원본 `../ev-map/data`를 읽기만 한다. 지도는 외부 지도 라이브러리 설치 없이 좌표 기반 SVG 선택 지도로 구성하며 도로 배경을 제공하는 지도와 구분해 표시한다.
- 예약·점유·주문·대기는 원본과 분리한 Git 제외 로컬 JSON 파일에 저장한다. 서버에서 확보 요청을 직렬 처리한다. 재시작 중 시간 경과 복구는 C-09 결정 전 완료 범위에 포함할 수 없다.
- 운전자 3개 테스트 계정 선택 방식으로 로그인한다. 서버에서 계정과 소유자 권한을 검사한다. 운영자 화면은 이번 요청 범위에 넣지 않는다.
- `.env`의 토스 테스트 키만 읽는다. 값은 문서·로그에 기록하지 않고, 비밀키는 서버에서만 사용한다. 키 준비 방식과 실제 연동 가능한 키 종류는 별도 확인한다. 성공 URL 이동만으로 예약을 확정하지 않는다.
- 기존 Vitest로 AC별 테스트를 먼저 작성하고 사용자 확인·Red 이후 구현한다. HTTP 검증과 모바일 브라우저 검증, 실제 토스 테스트 연결 결과를 각각 기록한다.

## 화면과 정책 적용 제안

지도·검색 → 충전기 상세·커넥터 선택 → 날짜·00/30분 시작·30/60/90분 길이 →
3,000원 테스트 결제 → 내 예약 순서로 구성한다. 점유 중과 승인 후 확정을 구분한다.
확정 예약과 유효 점유는 기존 `src/rules`의 겹침 판정을 호출하여 차단한다.

노쇼 버튼은 예약 상태를 즉시 강제로 바꾸는 대신, 시연용 시계를 해당 예약의
체크인 기한으로 진행하고 기존 노쇼 규칙을 호출하는 조작을 제안한다.
기존 정책은 일반 예약 시작 +15분 미체크인일 때만 노쇼를 허용한다
(US-16 / AC-16-1~3 / T-26, T-45 / C-09).
노쇼 환불은 0원이다. 대기자에게는 자동 확정이 아닌 3,000원 결제 요청과
10분 기한을 표시하고, 결제 승인 이후에만 승계 확정한다.

## 구현 전 필요한 확인

1. 위 구성의 저장·로그인·지도·검증·키 준비 방식 합의: C-10 / T-01.
2. 테스트 작성은 사용자가 `.codex/TEST_WRITING` 일반 파일을 직접 만든 이후 가능하다.
   에이전트는 이 스위치를 변경하지 않는다. 작성된 테스트의 별도 사용자 확인이 필요하다.
3. 예약 대상 24시간 문구 판정 C-05, 커넥터 선택·변경 C-11,
   결제창 닫기·실패·환불 실패 C-07은 해당 동작 구현 전에 답변이 필요하다.
4. 대기 동률·대기 상태 C-06, 예약 보유 첫 대기자 C-03,
   승계 잔여 30분 재검사·승인 후 부족 시 보상 C-01,
   승계 승인·기한 경합 C-04는 해당 동작 구현 전에 답변이 필요하다.
5. 시연용 시계 진행·복구 C-09와 제안한 노쇼 버튼 해석을 확인해야 한다.
   기존 확정 정책만으로 임의의 즉시 노쇼 처리나 모든 승계 경계를 구현하지 않는다.

## 현재 완료 근거와 한계

`src/rules`에는 겹침, 체크인, 환불, 결제 승인·웹훅 대조,
일반 노쇼·미결제 승계 요청 만료 함수가 있다. 웹 화면·HTTP 서버는 없다.
`package.json`에는 규칙 테스트와 타입 검사 명령만 있다.
`.env`와 `node_modules`의 존재만 확인했으며 키 유효성과 실제 연결은 확인하지 않았다.
이 제안 문서는 T-01 완료나 기능 구현·테스트 통과 증거가 아니다.

근거: `AGENTS.md`, `docs/prd.md`, `docs/acceptance.md`, `docs/tasks.md`,
`.specify/memory/constitution.md` III, `docs/harness.md`.
