# 수업용 예약 화면 구현 계획

승인 근거: 사용자 “좋아, 제안대로 진행해 … 새 테스트는 쓰지 않아도 돼 …
src/rules 함수를 그대로 부르고 … 미정 … 노쇼 버튼 … 체크인 기한”.
이번 화면에만 신규 테스트 작성 관문을 적용하지 않는다. 기존 테스트·규칙·훅은 변경하지 않는다.

구성: Node.js 24 내장 HTTP 서버, TypeScript 규칙은 런타임 타입 제거로 직접 호출,
HTML/CSS/JavaScript, 로컬 JSON 저장, 계정 선택 로그인, 토스 테스트 SDK CDN.
`docs/browser-preview-proposal.md`의 화면 흐름을 구현한다. 새 패키지 설치·배포 없음.

- [x] `src/preview/data.ts`: 원본 읽기·상태 병합·검색. 원래 수업 원본 경로 발견·연결.
- [x] `src/preview/store.ts`: 원본과 분리한 저장, 계정·시연 시계·주문·예약·대기 상태.
- [x] `src/preview/service.ts`, `payments.ts`: 기존 규칙 호출, 원자적 점유, 토스 승인 확인·보상 환불 호출 구현. 승인·환불 실제 완료 검증은 BLOCKED.
- [x] `src/preview/server.ts`: 루프백 HTTP, 세션·소유권·동일 출처 검사, 정적 파일·API.
- [x] `src/preview/public/`: 지도·충전소·시간·예약·대기·시연 시계·미정 안내·결제창.
- [x] 기존 규칙 검사·타입 검사, 새 파일 타입 검사, 브라우저 데스크톱/모바일 확인.
- [x] 실행 상태·주소·토스 실연결 범위를 문서에 기록.

토스 실제 승인 후 노쇼·승계 브라우저 통합은 NOT_RUN. 외부 카드사 인증 미완료를
구현 완료나 통합 검사 통과로 확대하지 않는다. 상세는 `browser-preview-validation.md`.

미정 동작은 성공을 꾸미지 않고 사유와 함께 차단한다. 데이터가 없으면 가짜 충전기를
생성하지 않는다. 결제 실패 재시도·승계 결제 재개방·환불 실패 재시도는 구현하지 않는다.
사용자 취소·운영자 기능·승계 체크인은 이번 화면 범위에 넣지 않는다.
대기자 예약 보유·동률, 승계 최소 잔여시간 경계·동시 승인도 미정으로 보류한다.
승계 최소 잔여시간 경계가 결제 중 발생할 수 있는 구간에는 결제창을 열지 않는다.

검토 중점: 키 비노출, 원본 불변, 서버 측 예약 충돌/계정 제한,
결제 성공 URL과 확정 구분, 미정 사례의 실행 차단, 모바일 가로 넘침.
