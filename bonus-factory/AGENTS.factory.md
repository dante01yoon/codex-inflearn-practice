## 소프트웨어 팩토리 규칙

이 저장소의 이슈는 `scripts/factory.sh` 라인으로 처리한다. 공정 하나가 스킬 하나(`.agents/skills/factory-*`)이고, 라인 스크립트가 부를 때만 실행한다.

| 분류 | 기준 | 다음 공정 |
|---|---|---|
| `fix` 바로 수정 | 재현 입력과 기대 결과가 이슈에 있고, 확정된 정책 안에서 고칠 수 있다 | 재현 테스트 → 수정 → 리뷰 → PR |
| `spec` 스펙 먼저 | 새 기능이거나 화면·결제·환불 동작을 새로 정해야 한다 | 스펙 문서 → 사람 승인 |
| `need-info` 정보 부족 | 재현할 입력이나 기대 결과가 없다 | 제보자에게 질문만 한다. 코드는 고치지 않는다 |
| `human` 사람 결정 | PRD의 미정 정책을 정해야만 한다 | 선택지만 정리한다. 코드는 고치지 않는다 |

- 추측으로 고치지 않는다. 실패하던 테스트가 통과하고 화면 증거가 있기 전에는 "고쳤다"고 쓰지 않는다.
- 기존 테스트는 사람의 기준이다. 재현 테스트는 재현 공정에서 `tests/rules/issue-<번호>.test.ts` 새 파일에만 쓴다. 수정 공정에서는 `tests/`가 잠긴다.
- GitHub 쓰기(라벨·댓글·PR)는 라인 스크립트가 한다. 코덱스는 결과를 파일과 마지막 응답으로만 남긴다.
- 머지는 사람이 한다. 보고와 PR 본문은 한국어로 쓴다.
