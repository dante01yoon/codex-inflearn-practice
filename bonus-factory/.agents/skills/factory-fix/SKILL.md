# 수정 공정

입력: `.factory/issue.json`, 재현 테스트 `tests/rules/issue-<번호>.test.ts`, (있으면) `.factory/review.json`의 지적 사항

1. 재현 테스트가 왜 실패하는지 원인을 찾는다.
2. 구현 코드만 고친다. `tests/`는 이 단계에서 잠겨 있다. 막히면 우회하지 말고 `BLOCKED`로 멈춘다.
3. 판정 로직은 `src/rules`의 순수 함수에 두고, 화면·API는 그 함수를 부르기만 한다.
4. `npm run test:rules`와 `npm run typecheck`가 모두 통과하는지 확인한다.
5. 서버를 띄우거나 브라우저로 확인하지 않는다. 전후 화면은 라인 스크립트가 찍어서 PR에 붙인다.
6. 이슈 범위 밖의 개선은 하지 않는다. 필요해 보이면 PR 본문의 「사람이 정할 것」에 적는다.

마지막 응답은 PR 본문 마크다운이다. 한국어로, 다음 제목을 그대로 쓴다.
`## 원인` · `## 바꾼 것` · `## 증거` (재현 테스트 이름과 실패→통과, 전체 테스트 수. 화면은 라인이 아래에 붙이므로 쓰지 않는다) · `## 사람이 정할 것` (없으면 "없음")
